# intl Localization Migration — Design Spec

**Date:** 2026-08-27
**Status:** Approved (session brainstorming, decisions recorded below)
**Scope:** `formularium`, `formularium_decimal`, `formularium_flutter` + example app (monorepo `formularium/`)

## Problem

The packages localize validation messages through `concierge` (`IContext` service locator) +
`localization_interface` (`ILocalizable.localize(IContext)`), with messages generated by
`flutter gen-l10n` into `AppLocalizations` (Flutter-bound). Validators run in pure Dart, so a
context must be threaded everywhere; the message store transitively depends on Flutter
(`dart:ui`, `flutter_localizations`).

## Decisions (binding)

1. **Approach 3 — keep `ILocalizable`, drop the `IContext` stack.** The message-carrier
   abstraction survives; its signature becomes context-free.
2. **New package `formularium_localization`** (pure Dart, zero deps) hosts:
   - `abstract interface class ILocalizable { String localize(); }`
   - `class CurrentL10n<T>` — global holder: `resolve()` fallback + test override + `reset()`.
   - Dropped from the old contract: `Localizer<T,R>`, `DelegateLocalizable`, `ILocalizable.delegate` (verified unused).
3. **intl-native resolution.** Locale source of truth = `Intl.defaultLocale`. Messages generated
   from the existing ARBs by **`intl_translation ^0.21.0`** (`extract_to_arb` + `generate_from_arb`)
   producing pure-Dart `Intl.message` functions. gen-l10n is removed entirely
   (`l10n.yaml`, `lib/l10n/generated/`, `generate: true`, `flutter_localizations` dep).
4. **Flutter-free localizations.** Every localizations layer must have zero
   `package:flutter/...` imports. Flutter shrinks to ONE delegate file per Flutter package
   whose `load()` sets `Intl.defaultLocale`, runs `initializeMessages` +
   `initializeDateFormatting`, and returns the pure-Dart messages object.
5. **Per-package global accessors** backed by `CurrentL10n<T>`:
   - formularium: `fL10n` / `set fL10n` / `resetF10n()` / `initFormulariumL10n([locale])`
   - formularium_decimal: `fdL10n` / `set fdL10n` / `resetFdL10n()` / `initFormulariumDecimalL10n([locale])`
   - formularium_flutter: `ffL10n` / `set ffL10n` / `resetFfL10n()` / `initFormulariumFlutterL10n([locale])`
6. **All three packages migrate** (they implement the same shared `ILocalizable`).
7. **`listenable_plus` and `reef_utils` stay outside** the monorepo (path overrides to
   `../my_packages/`). `concierge` + `localization_interface` are temporary members, deleted at the end.
8. **Breaking change, clean cut** (0.0.x): no deprecated shims. CHANGELOG documents the
   third-party migration (import / signature / resolution / call sites).

## Accepted trade-offs

- Breaking: `localize(IContext)` → `localize()`; `IContext` threading removed everywhere.
- `initializeDateFormatting` becomes mandatory for non-en date formatting (was silently en-only).
- `intl_translation` is aging tooling — accepted by product owner.
- Message keys/function names stay snake_case (matching ARB keys); template locale is **pt**.

## Target architecture

```
formularium_localization (pure Dart, 0 deps)
  ├─ ILocalizable { String localize(); }
  └─ CurrentL10n<T>

formularium / formularium_decimal / formularium_flutter (each):
  ├─ pure Dart:  IXLocalizations interface + XMessages (Intl.message delegates)
  │              + global fX10n accessor (CurrentL10n) + init/reset
  └─ ONE Flutter adapter file: LocalizationsDelegate syncing Intl.defaultLocale
```

Runtime flow: `MaterialApp → delegate → Intl.defaultLocale → Intl.message lookup → message`.
Pure-Dart consumers call `initXL10n()` directly.
